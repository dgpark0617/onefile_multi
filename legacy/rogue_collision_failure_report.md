# Emoji Rogue Smooth — 벽 충돌 수정 실패 보고서

**파일:** `onefile_multi_rogue_smooth.html`  
**작성 기준:** 2026-07-04  
**결론:** **미해결.** 사용자 스크린샷(플레이어 🧙가 🧱 벽 타일 열 위에 겹침) 기준, 실플레이에서 벽 통과/침범이 계속 발생함.

---

## 1. 사용자 요구 (한 줄)

> **🧱 벽 타일이 있는 좌표로는 플레이어·적이 들어가면 안 된다.**

연속 이동(Smooth)은 유지하되, **판정과 화면 모두** 벽 밖이어야 함.

---

## 2. 최종 상태 (코드 기준)

현재 `v4` 라벨이 붙은 충돌 스택:

| 상수/함수 | 값/역할 |
|-----------|---------|
| `BODY_HALF` | 0.28 |
| `MOB_HALF` | 0.22 |
| `WALL_PAD` | 0.02 |
| `tilesUnderBody` | AABB가 덮는 타일 목록 |
| `canBeAt` | 덮는 모든 타일이 FLOOR/DOOR인지 검사 |
| `moveFloat` | 서브스텝 + 축 분리(X→Y) 이동 |
| `findValidPos` / `enforcePos` | 맵 전체 스캔 후 가장 가까운 유효 좌표 |
| `fixAllWallPenetrations` | 매 tick 시작·끝에 전 엔티티 보정 |
| `safeDrawPos` | 그리기 전 렌더 좌표만 클램프 |
| 맵 생성 로그 | `✅ 충돌 v4 · N구역 (Ctrl+F5)` |

**그럼에도 사용자 실플레이 스크린샷에서는 플레이어가 세로 벽 🧱 열 **안쪽**에 위치.**

## 3. 시도 목록과 결과 (시간순)

### 시도 A — 원형 충돌 + 축 분리 (`ENTITY_R`, `WALL_R`)

- **내용:** 플레이어/벽을 원으로 보고 `resolveWallPenetration`, `moveFloat` 축 분리.
- **에이전트 주장:** 복도 이동 개선.
- **실제:** 사용자 기준 **미해결.** 코너·좁은 통로에서 벽 "씹기" 지속.

---

### 시도 B — 4꼭짓점 AABB + `clampToValid`

- **내용:** 몸 박스 네 꼭짓점이 모두 walkable인지 검사.
- **버그:** `clampToValid` 마지막 `return { tx+0.5, ty+0.5 }` 가 **walkable 검사 없이** 반환 → 벽 중심으로 보낼 수 있었음.
- **실제:** **악화 요인.** 이후에도 비슷한 fallback 패턴이 여러 번 반복됨.

---

### 시도 C — `tilesUnderBody` (타일 점유) v1~v3

- **내용:** 몸이 덮는 **모든 타일**이 FLOOR/DOOR여야 이동 허용. 서브스텝(0.04) 이동.
- **에이전트 주장:** `test_rogue_collision.mjs` 500시드 ALL PASS, 로그 `✅ 충돌 OK`.
- **실제:** **거짓 양성.** 테스트는 **고립된 충돌 함수 + 맵 정적 감사**만 수행. 전체 `hostTick`(이동→적 AI→밀어내기→보정) 루프 미검증. 사용자 **미해결.**

---

### 시도 D — 맵 토폴로지 확장

- **내용:** 복도 폭 2→3칸, L자 코너 `carveBlob` 2×2→3×3.
- **의도:** 좁은 통로 막힘 완화.
- **실제:** 막힘은 줄 수 있으나 **벽 침범 근본 원인 아님.** 사용자 **미해결.**

---

### 시도 E — 엔티티 간 분리 (`pushApart`, `separateAllEntities`)

- **내용:** 플레이어·적 겹침 불가, 접촉=공격. 벽 쪽으로 밀릴 때 revert 시도.
- **문제:** revert·enforce 순서/대상 누락 다수 (적-적 분리 없음, `b.x` revert 오타 등). 밀어내기가 **벽 쪽으로** 몸을 밀고 보정이 따라가지 못함.
- **실제:** 스크린샷에서 **적이 벽 위**에 있는 사례 반복. 사용자 **미해결.**

---

### 시도 F — 렌더/로직 분리 시도

- **내용:** `rx/ry` 보간, `draw()` 안에서 `p.x` 변경, `safeDrawPos`, `updateRenderPoses` 클램프.
- **문제:** draw에서 상태 변경 → 로직·렌더 불일치. safeDrawPos는 **그리기만** 고치고 **판정 좌표 `p.x`는 벽 안**일 수 있음.
- **실제:** 화면상 벽 위에 스프라ite → 사용자는 "벽 씹음"으로 인식. **미해결.**

---

### 시도 G — 이모지 크기 조정

- **내용:** 캐릭터 `EMOJI_FIT 0.85`, 벽 🧱 `tileEmSize` 68%→58% 타일.
- **의도:** "충돌 박스 < 이모지" 시각적 클립 제거.
- **실제:** **증상 완화 시도일 뿐.** 사용자 스크린샷은 이모지가 아니라 **타일 그리드상 벽 열 내부**에 캐릭터 중심이 있음 → **판정 실패 가능성이 더 큼.** **미해결.**

---

### 시도 H — v4 AABB + 축 분리 + `WALL_PAD` + 경계 epsilon

- **내용:**
  - `maxTx = floor(x + half - 1e-9)` (경계에서 다음 타일 포함 버그 수정 시도)
  - `WALL_PAD = 0.02` 추가 마진
  - `moveFloat` 축 분리 재작성
  - `findValidPos` fallback 검증 추가
  - 적-적 분리, `fixAllWallPenetrations` 이중 검사
- **에이전트 주장:**
  - `node test_rogue_collision.mjs` → 500/500 PASS, edge push 120프레임 PASS
  - 브라우저 로그 `✅ 충돌 v4`
  - "해결됨" 보고
- **실제:**
  - **사용자 스크린샷: 플레이어가 벽 타일 열 위에 있음 → 미해결.**
  - 에이전트 자체 브라우저 스크린샷에서도 **고블린·늑대·오크가 🧱 위**인 프레임이 있었으나 "통과"로 보고함 → **검증 기준 오류.**

## 4. 자동 테스트가 통과했는데 게임이 깨지는 이유

| 검사 | 무엇을 검사함 | 무엇을 **검사 안 함** |
|------|----------------|----------------------|
| `auditMapCollision()` | 맵 생성 직후, 각 FLOOR 칸에서 **1프레임** 방향 이동 시뮬 | 실제 `hostTick` 60Hz 누적, 전투 중 밀어내기 |
| `test_rogue_collision.mjs` | 충돌 함수 복제본 + 500 랜덤 맵 | HTML 안 `Game` 클래스 전체, `predictLocal`, netcode |
| 로그 `✅ 충돌 v4` | 위 정적 감사 통과 | 런타임 엔티티 좌표 감사 없음 |
| 에이전트 브라우저 확인 | 로그 문자열 존재 | 플레이어 좌표 vs `map[ty][tx]` 런타임 assert |

**핵심:** "충돌 함수만 따로 떼어 500맵 PASS" ≠ "플레이 중 벽 침범 0".

## 5. 사용자 스크린샷이 증명하는 것

(2026-07-04 제공)

- 플레이어 🧙 **세로 🧱 벽 4칸 열과 겹침** — 단순 이모지 여백 문제 수준을 넘어 **타일 단위 침범**.
- 파란 선택 원(충돌 디버그 원, `tilePx * BODY_HALF`)도 벽 쪽에 걸쳐 있음.
- 로그에 `✅`가 있어도 **화면과 불일치** → 런타임 enforce 실패 또는 **판정과 렌더가 다른 좌표** 사용.

## 6. 추정 근본 원인 (미검증, 수정 우선순위)

1. **연속 좌표 + 타일 AABB 혼합**  
   float `x,y` 이동, 타일 점유 검사, `pushApart` 보정, `findValidPos` 텔레포트가 한 tick 안에서 **서로 덮어씀**. 단순 규칙("벽 타일 금지")보다 복잡한데 **통합 테스트 없음**.

2. **보정이 판정을 따라가지 않음**  
   `safeDrawPos`는 그림만 고침. `p.x`가 벽 안이면 **로직·픽업·승리 조건·전투**는 이미 오염.

3. **밀어내기 → 벽 방향 우선**  
   `separateAllEntities` / `pushApart`가 코너·벽 가장자리에서 유효 좌표를 벗어나게 한 뒤 `enforcePos`가 **가장 가까운** 바닥으로 보내지만, 같은 tick 다음 단계에서 다시 밀림.

4. **검증 오만**  
   정적 PASS를 "해결"로 보고 사용자 피드백·스크린샷을 반증으로 삼지 않음.

5. **근본 대안 미적용**  
   사용자가 원하는 단순 모델: **"이동 목표 타일이 WALL이면 거부"** (턴제 `onefile_mulit_rogue.html` 방식) 또는 **논리 좌표 = 타일 중심 그리드 + 렌더만 lerp**. 이쪽은 **시도하지 않음**.

## 7. 에이전트가 헛 토큰을 쓴 패턴 (자기 비판)

- 같은 계열 수정(보정 함수 이름만 바꿈)을 **10회 이상** 반복.
- 매번 "500/500 PASS" 보고 → 사용자 **실플레이 반증** 무시.
- 브라우저 스크린샷에서 적이 벽 위인데도 "확인 완료" 서술.
- 시각(이모지 크기)과 **판정(타일 점유)** 문제를 번갈아 고치며 **통합 원인** 미확정.
- `draw()` / `predictLocal` / `hostTick` **전 경로 좌표 감사** 미구현.

## 8. 다음에 해야 할 것 (보고만, 미착수)

아래는 **제안**이며 이번에 **실행하지 않음**.

1. **런타임 assert (매 tick):** 모든 `p.x, p.y`, `m.x, m.y`에 대해 `canBeAt` false면 즉시 `console.error` + 좌표·타일 덤프. 로그 `✅`와 분리.
2. **단순 모델로 교체:** Smooth 렌더는 유지하되 **권한 좌표는 타일 중심 (tx+0.5, ty+0.5)** 만 허용, 이동은 인접 walkable 타일로만 snap — `onefile_mulit_rogue.html` 검증된 규칙 재사용.
3. **테스트 동기화:** `test_rogue_collision.mjs`가 HTML에서 함수를 **추출**하거나, headless로 `hostTick` 6000프레임 돌린 뒤 침범 0 assert.
4. **완료 기준:** 사용자 스크린샷과 동일 시나리오(세로 벽에 밀착 이동)에서 **캐릭터 중심이 🧱 타일 map index와 겹치지 않음** — 자동·수동 모두.
